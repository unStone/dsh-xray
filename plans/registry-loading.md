# 注册表加载性能修复

## 问题与验收

注册表首屏依赖全量 `data.json`，并为全部仓库生成含隐藏详情的 DOM；首页仅需统计也下载该文件。截图中的请求传输约 4 MB、耗时 55 秒。

| 路径 | 修改 | 验收 |
|---|---|---|
| 数据生成 → 页面首屏 | 从当前完整快照生成统计、首批 50 条摘要和带内容哈希的搜索索引、详情分片；首批摘要内嵌 HTML | 禁止全量数据请求后，首屏和统计仍可显示；首屏摘要含全部旗标 |
| 搜索 / 筛选 → 分页 | 精简索引仅保留搜索和列表字段，交互时加载；每页 50 条 | 搜索最后一条仓库及服务名、等级和可安装筛选、翻页均正确；DOM 行数不超过 50 |
| 展开 → 证据 | 点击后获取相应详情分片，保留完整静态分析证据 | 注册位置、partial / deferred、未扫描、徽章复制和深链接保持可用；请求失败显示可重试错误 |
| 扫描 → 发布 | 生成步骤纳入每日扫描，保留上一代哈希资源避免缓存页面引用失效 | 完整生成数据守恒；连续生成与旧版本资源保留测试；线上 Pages 实测 |
| 首页 → 统计 | 改为独立统计 JSON | 不请求全量数据，数字与快照一致 |

## 实施顺序

1. 先添加生成器契约测试，验证真实数据分片重组、字段完整性、安全内嵌、确定性和上一代资源保留。
2. 实现生成器并用当前发布快照构建资源；完整 `data.json` 保留现有机器消费者契约。
3. 替换注册表调用方，加入分页、延迟详情与失败重试；补齐三语文案并修改首页统计加载。
4. 将生成器接入扫描工作流和检查，执行自动测试、真实浏览器桌面 / 手机 / 慢网络和故障验证。
5. 检查差异后合并发布，重新验证线上资源和交互，记录传输大小及实际测量结果。
